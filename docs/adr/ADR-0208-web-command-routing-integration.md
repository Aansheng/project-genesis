# ADR-0208: Web Command Routing Integration

**Status:** Accepted  
**Date:** Sprint 10  
**Work Order:** WO-S10-004  
**Architecture Version:** v1.94 → v1.95

---

## Context

The system has the `IntentRouter` and `CreateWorldRuntimeExecutor` primitives, but `apps/web` still routes user commands through the legacy `MockPlanner` → `DefaultPipeline` → `runtime.applyActions()` path. When a user types "创建 MarioWorld", the system routes it through `MockPlanner.plan()` which returns mock actions, not the real `CreateWorldPipeline`.

### Problem

1. **Legacy MockPlanner dependency** — `gameStore` constructs a `MockPlanner` and `DefaultPipeline` for every command
2. **No CommandExecutor abstraction** — command routing logic is coupled to the Pinia store
3. **No RuntimeWorldStore integration** — worlds generated by the AI pipeline are not injected into the rendering loop
4. **No CreateWorldRuntimeExecutor integration** — the existing pipeline runner is not connected to the web UI

### Scope Boundaries

- No changes to the `Runtime` package
- No changes to the `Renderer` package
- No changes to AI pipeline implementation (`DefaultPipeline`, `MockPlanner`, `AgentLoop` preserved)
- Only connect `apps/web` to existing architecture

---

## Decision

Introduce a `CommandExecutor` abstraction in `apps/web/src/command/` that routes user commands through the existing `IntentRouter` → `CreateWorldRuntimeExecutor` → `RuntimeWorldStore` chain.

### Architecture

```
User Input (string)
    ↓
DefaultCommandExecutor.execute(input)
    ├── IntentRouter.route(input)
    │   ├── route = "create-world"
    │   │   └── CreateWorldRuntimeExecutor.execute(input)
    │   │       ├── CreateWorldPipeline.execute()
    │   │       │   ├── IntentRouter
    │   │       │   ├── GameIntentExtractor
    │   │       │   ├── SemanticWorldGenerator
    │   │       │   ├── SemanticGameDslBuilder
    │   │       │   └── RuntimeProjection
    │   │       └── worldStore.setWorld(world)  ← side effect
    │   └── route = "unknown"
    │       └── return { success: false, message: "Unknown command" }
    ↓
CommandExecutionResult { success: boolean, message: string }
```

### Changes to gameStore

| Removed | Added |
|---------|-------|
| `MockPlanner` | `DefaultCommandExecutor` |
| `createProvider()` | — |
| `DefaultPipeline` | — |
| `pipeline.execute()` / `pipeline.stream()` | `commandExecutor.execute()` |
| `formatWorldState()` | — |
| `applyResult()` | — |
| `memory` / `DefaultMemory` | — |
| `streaming logic` (active) | `streaming state` (inert — UI preserved) |

- World rendering source changed from `Runtime.world` to `RuntimeWorldStore.getWorld()`
- Chat history (log array) preserved
- Streaming toggle UI preserved (inert — no longer affects command routing)

### New Module: `apps/web/src/command/`

| File | Purpose |
|------|---------|
| `CommandExecutionResult.ts` | `{ success: boolean, message: string }` |
| `CommandExecutor.ts` | Interface with `execute(input): CommandExecutionResult` |
| `DefaultCommandExecutor.ts` | Routes via `IntentRouter` → delegates to `CreateWorldRuntimeExecutor` |
| `index.ts` | Barrel exports |

### Package Export Added

- `packages/ai/src/index.ts` now exports `DefaultCreateWorldRuntimeExecutor`
- This is a packaging change only — no AI pipeline logic was modified

---

## Consequences

### Positive

1. **Legacy MockPlanner removed** from `apps/web` — command routing now uses the real architecture
2. **RuntimeWorldStore integrated** — AI-generated worlds are injected into the rendering source
3. **Chat history preserved** — log messages still display in the conversation panel
4. **Streaming toggle preserved** — UI remains unchanged, command routing unaffected
5. **Zero behavioral changes** to Runtime, Renderer, or AI packages
6. **Testable CommandExecutor** — new integration tests verify end-to-end flow

### Negative

1. **Synchronous execution** — `CreateWorldRuntimeExecutor.execute()` is synchronous; the streaming UX path is inert
2. **No fallback for unknown commands** — "hello world" returns `{ success: false, message: "Unknown command" }` with no AI fallback

### Neutral

1. `MockPlanner`, `DefaultPipeline`, `DefaultMemory` remain available in `@genesis/ai`
2. `Runtime` class instance retained in `gameStore` for backward compatibility
