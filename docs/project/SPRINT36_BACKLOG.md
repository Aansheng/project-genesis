## WO-S36-001 — Generic Active-World New-World Intent Classification

status: **DONE — Code Complete = YES; Product Verified = YES**
priority: **P0**  
architecture_before: v1.185  
architecture_after: v1.186

### Mission

Make the existing Intent/front-door boundary distinguish a generic new
whole-world/game request from a mutation of the active world. Preserve the
existing CreateWorld pipeline, World Evolution candidate validation, Runtime
authority, Renderer authority, and state/replacement contract.

### Measured bottleneck

With an active world, `DefaultIntentRouter` returns `unknown` for
`创建 MarioWorld`, `创建一个 RPG`, and `生成一个幸存者游戏`. The Web front door
then treats active `unknown` as an Evolution opportunity. The mutation-only
World Evolution prompt/planner cannot create a replacement world, so the
request fails and the active world remains unchanged. `创建一个新的游戏`
already reaches CreateWorld, proving the replacement pipeline exists.

### Allowed scope

- Minimal change to the existing IntentRouter/front-door classification
  boundary and its deterministic precedence.
- Generic signal predicates for current-world mutation versus whole-world
  creation; no individual genre/name registry.
- Unit tests for active and inactive routing using the authorized A/B/C/D
  matrix.
- Web production-path tests proving CreateWorld replacement versus same-world
  Evolution and ambiguity safety.
- Existing route/evolution/CreateWorld observability needed to prove which
  pipeline ran.
- Required project/control-plane documentation and completion evidence.

### Required routing contract

1. Current-world mutation signals take priority: entity target plus quantity,
   property/evolution intent, and continuation language remain World
   Evolution.
2. Explicit new/reset language remains CreateWorld with or without an active
   world.
3. A generic whole-world/game scope plus creation/construction or
   named/archetype evidence, with no current-world mutation signal, reaches
   the existing CreateWorld route even when a world is active.
4. Bare or underspecified creation (`创建`, `生成一个`, `做一个新的`) remains
   non-replacing. If active-world AI fallback is retained, only an AI-validated
   World Evolution delta can apply under the existing validation/revision
   guards.
5. Provider output remains a candidate only. No provider may directly replace
   a world, and no second routing layer may be introduced.

### Acceptance matrix

| Input class | Required behavior with active world |
| --- | --- |
| `创建 MarioWorld` | CreateWorld; replace current world identity; no Evolution operation |
| `创建一个 RPG` | CreateWorld; replace current world identity; no Evolution operation |
| `生成一个幸存者游戏` | CreateWorld; replace current world identity; no Evolution operation |
| `做一个农场游戏` | Generic whole-world construction → CreateWorld; no genre-specific branch |
| `创建一个新的游戏` | Existing explicit-new CreateWorld behavior remains |
| `重新创建一个平台跳跃游戏` | Existing explicit-new CreateWorld behavior remains |
| `新建一个农场游戏` | Existing explicit-new CreateWorld behavior remains |
| `再加五只怪` | World Evolution; same world; existing bounded delta behavior remains |
| `再创建5个怪物` | World Evolution; same world; existing quantity/entity precedence remains |
| `再加两个金币` | World Evolution; same world; no CreateWorld route |
| `增加一个 Boss` | World Evolution; same world; no CreateWorld route |
| `删除一个敌人` | World Evolution candidate path; no CreateWorld route |
| `创建` / `生成一个` / `做一个新的` | No world replacement; remain ambiguous/non-replacing |

The future implementation must verify actual world IDs, not only route enum
assertions. A successful active new-world command must use the existing
CreateWorld replacement path, create a new world identity, and rebind the
existing semantic/gameplay/Runtime/Observatory projections. A current-world
mutation must retain its world identity and evolution lineage.

### AI and fallback boundary

CreateWorld requests continue through the existing world-generation provider
and deterministic fallback, followed by the existing validated pipeline.
World Evolution requests continue through the existing structured AI candidate
provider and Genesis validation. Ambiguous input must not be converted into a
provider-direct world replacement. No `IntentManager`,
`ConversationManager`, `RoutingEngine`, NLP framework, AI world authority, or
second router is allowed.

### Observability requirements

- Active named/whole-world creation shows a world-generation/CreateWorld
  lifecycle, a new current world ID, and no World Evolution operation for the
  same command.
- Active mutations retain current operation ID, world ID, semantic revision,
  Runtime synchronization, and visual synchronization lineage.
- Failed or ambiguous requests leave the current world ID and committed
  Runtime state unchanged.
- Existing Observatory metadata remains truthful at v1.186 if the
  implementation advances the architecture version.
